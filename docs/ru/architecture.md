# Архитектура

Пакет построен как небольшая гексагональная композиция.

## Ядро

`contracts/`, `registry.py` и `runtime.py` содержат декларации, проверяемые модели отображения,
регистрацию и правила URL. Ядро ничего не знает о базе данных, ORM или конкретной аутентификации.

## Порты проекта

Подключающий проект предоставляет:

- провайдеры данных для страниц и виджетов;
- провайдер прав `can(request, permission)`;
- обработчики изменяющих операций;
- при необходимости контекст дашборда и значения бейджей.

Бизнес-логика остаётся в проекте — рядом с его транзакциями и политиками.

## Адаптеры FastAPI и Jinja

`CabinetSite` превращает реестр в маршруты FastAPI. Мапперы проверяют результат провайдера до
передачи во встроенные Jinja-шаблоны. `include_cabinet` подключает роутер и статические ресурсы.

```text
Запрос FastAPI
    -> маршрут CabinetSite
    -> проверка прав
    -> провайдер / операция проекта
    -> проверяемая модель страницы или виджета
    -> Jinja
    -> HTML
```

Игровые и другие продуктовые страницы не входят в ядро. Они живут в frontend/admin-части
подключающего проекта и используют библиотеку как общую основу.
